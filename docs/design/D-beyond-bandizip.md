# D — 在哪里超越 Bandizip（差异化，但不增加学习成本）

> 范围：只做研究与设计判断，**不改代码**，不提交。
> 日期：2026-11-07。作者：设计评审（子代理 D）。
> 输入：4 张实测截图（E:\Project\7zip-prism-archive\docs\assets\ui\audit-*.png）、既有审计 docs/UI-AUDIT-BANDIZIP.md、
> 本机 Bandizip 6.29.0.1（2020-09-14 构建）的二进制与内嵌 manifest、docs/DESIGN.md 令牌表。
> 本文**不重复** UI-AUDIT-BANDIZIP 已下的结论（默认网格、四列缺失、蓝文件夹、浮动岛、光晕根因）；
> 只在需要引用时给编号。

---

## 0. 一页结论

1. **Bandizip 的真实短板只有三类**，而且都不是"功能少"，是**"状态不可读"**：
   位置不可读（没有路径）、会话不可读（一次一个包）、像素不可信（system-DPI + 一套 GDI 浅色皮）。
2. **五个安静的超越点**全部落在**已有坐标**上：按需标签、路径尺、会说话的状态栏、缩略图预算、输入模态焦点。
   五个里只有第一个新增了元素，其余四个是"同一个位置，更好的信息"。
3. **签名设计选「一线」（The Seam）**：全产品只有一条 2px 强调线，它在哪，你就在哪。
   现状已经有三种蓝在抢这个角色（#0A84FF 选择条 / #0A79EB 标签下划线 / #2480DF 文件夹填充），
   统一它们本身就是一次"看起来变贵了"的升级，且零学习成本。
4. **铁律**：不新增面板、不新增工具栏、不新增模态框。谁想加，先证明它不占新的坐标。
5. **前置条件**：在把光晕修干净之前，任何"更酷的暗色玻璃"都是负资产——
   实测图块外 50–70px 的泛光把卡片底从 #1E1F25 抬到 #5B2A29（ΔL\* ≈ 11.9），
   这是"看起来脏"，不是"看起来高级"。

- **缩放：两张图同为 125%（120 DPI），所以像素可以直接比。**

## 2. Bandizip 的三个真实短板

> 写法约定：每条给 **证据 / 它为什么没做（推断，明确标注）/ 迁移用户会不会被吓到 / 我们的边界（红线 + 数值）**。
> "为什么没做"全部是推断，因为商业决策没有公开记录；我按架构年代和产品漏斗给最省力的解释。

### S1 — 位置不可读：全窗没有"路径"，列表里也没有 ".."

**证据**

1. 截图：工具栏（y 63–163）与列头（y 164–189）之间**没有任何路径元素**；整窗 0 个路径控件。
2. 工具栏 9 个按钮：打开 / 解压 / 新建 / 添加 / 删除 / 测试 / 查看 / 代码页 / 视图切换（右上角 2×2 图标）
   —— **没有"上一级"**。
3. 列表里**没有 ".." 行**：fixture.zip 根目录只有 docs / photos / src / data.bin / readme.md。
4. 于是"我在哪"只存在于左树的选中项里；路径一深，选中项会被滚出视野（树 246 px 宽、24 px 行高，约 21 行可见）。

**它为什么没做（推断）**
Bandizip 的导航模型是「树即位置」：打开归档 → 解包出目录树 → ListView 渲染当前树节点的子项。
"位置"不是一个值，而是 TreeView 的选中状态。加面包屑等于先把 path 提升为一等状态，
再定义 path ↔ tree 的双向同步（点树里折叠的祖先、点路径里树没展开的节点、点的顺序不同要收敛到同一结果），
还要处理长路径溢出——这是导航层重构，而 6.x 是只修安全的分支。
产品侧也没有动力：主流漏斗是「双击压缩包 → 解压全部 → 关闭」，根本不进深层目录。

**会不会吓到迁移用户**：**不会**，前提是它**只读 + 可点**。
它不新增入口，只是把"树的选中项"这件事翻译成一行可读的文字；点一段 = 点树的那个节点，语义是旧的。

**我们的边界（红线 + 数值）**
- 不做可编辑地址栏。一旦能输入，就要背自动补全、非法路径提示、UNC、\\\\? 长路径四份债。
- 路径条左端必须与列表首列文字左端对齐（现状是居中，见 Q2）。
- 段命中区 ≥ 24 × 24，且**无障碍树里每段一个节点**（现审计 §2.3 已证明整条是一个 listbox，读屏点不到）。

### S2 — 会话不可读：一次只能看一个包，关窗即失忆

**证据**

1. 标题栏 "fixture.zip - Bandizip 6.29"：单文档，无标签条（工具栏与列头之间没有 32 px 的标签带）。
2. 二进制里唯一的 Tab 控件是设置对话框的 SysTabControl32。
3. 对比两个包 = 两个窗口 + 两次 z-order 切换；关掉窗口，滚动位置、选中、排序全丢。

**它为什么没做（推断）**
单文档窗口是 2005 年 Windows 工具的默认心智（一个文件一个窗口，靠任务栏切换）。
多标签要求引擎句柄、目录缓存、选中集、滚动位置、排序列**全部 per-tab 化**，
而他们的封装更像"进程级单例"。商业上，标签不增加付费转化——它服务的是"同时处理多个包"的少数场景。

**会不会吓到迁移用户**：**会。这是五条里唯一一条新增元素的**。
Bandizip 用户打开一个包时，屏幕上不该多出一条他没要求过的横条。
→ 所以标签必须**迟到**：只在第二个包出现（Q1）。

**我们的边界**
- 1 个包 = 0 像素额外 chrome（与 Bandizip 完全一致）。
- 2 个包才出现 32 px 标签带；关闭回落到 1 个时整条消失（内容上移 32，同一段 160 ms 动效）。
- Ctrl+W / 中键 / Ctrl+Tab 三件套必须与浏览器一致；关最后一个标签 ≠ 退出程序，但**必须给出"打开 / 拖入 / 最近"三选一的空状态**，不能只剩一张白脸。

### S3 — 像素不可信：一套 2005 年的 GDI 浅色皮肤 + system-DPI

**证据**

1. manifest 写死 **dpiAware=true**（system DPI）：窗口跨到另一块不同缩放比的显示器时被整窗位图拉伸，字会糊，
   且必须重启才能重新按新 DPI 排版（PerMonitorV2 才解决）。
2. 绘制栈是 comctl32 6.0 + GDI owner-draw：截图里工具栏是一条逐行变化的渐变（#5BA7E4 → #077BD7），
   图标是约 26 逻辑 px（32 设备 px）的单色线性图，没有任何 Mica / 圆角 / 深色表面。
3. 白字在 #0078D7 上是 **4.50:1**——正好压在 AA 线上；渐变顶部 #5BA7E4 只有 **2.59:1**。
   也就是说它的工具栏对比度是**随 y 变化的**，越靠上的像素越不合格。

**它为什么没做（推断）**
GDI + common-controls 的主题化 = 重画每一个控件（工具栏、树、列表、滚动条、状态栏、对话框），
收益是"符合 Win11 审美"，成本是整条 UI 层；而 6.x 是维护分支。
system-DPI 的 manifest 是 2006 年那行，没人回头改；PerMonitorV2 需要把每个像素常量都改成 DIP 计算。
至于深色：他们要同时保证 2000 万下载量的浅色用户不变，稳定的做法就是"不加"。

**会不会吓到迁移用户**：**会，而且是在第一秒**——如果我们的默认是深色。
今天四张审计截图全是深色（画布 #0C0D11），而 Bandizip 是全白。用户点开我们的第一反应不是"更漂亮"，是"这不是同一个东西"。
所以这条的"超越"不是"我们有深色"，而是**两套主题都干净**：
- 首次启动 **跟随系统**；设置里 外观 = 跟随系统 / 浅色 / 深色 三选一；
- 浅色主题的硬指标照抄 Bandizip 的可用性下限：列表 #FFFFFF、正文与底色对比 ≥ 15:1（它 21:1）、状态条 #F0F0F0；
- 深色主题的对比度下限：**次要文字 ≥ 7:1**（我们现在状态条只有 4.59:1，没有余量）、
  表面之间的"抬升"必须靠 **1 px 边缘光**而不是靠提亮底色（实测：岛 #1A1D25 对画布 #0C0D11 只有 **1.15:1**，
  路径条 #20242E 对画布 1.25:1 —— 现在的层级几乎完全靠那条 1px 边撑着，这是对的，要继续）。

**我们的边界**：主题切换只换色，不换布局、不换图标、不换间距。任何一个"深色下重排"的方案都是在制造第二套肌肉记忆。

## 3. 五个"安静的超越点"

### 3.0 判据：迁移成本 = 新元素 × 新位置 × 新语义

一条建议要算"安静"，必须**最多只有一项是"新"的**，另两项是用户已经会的。
五个点里四个是"0 新元素 + 0 新位置"（只是同一位置的信息变好），
唯一的新元素（标签带）被推迟到用户主动做第二件事时才出现。

| # | 点 | 新元素 | 新位置 | 新语义 | 判定 |
|---|---|---|---|---|---|
| Q1 | 按需标签 | 有（≥2 包） | 有 | 无（同浏览器/资源管理器） | 唯一需要克制的一项 |
| Q2 | 路径尺 | 无 | 无 | 无（=点树节点） | 最安全，优先级最高 |
| Q3 | 状态栏是活的 | 无 | 无 | 无（同资源管理器） | 安全 |
| Q4 | 缩略图预算 | 无 | 无 | 无 | 安全（网格本来就是选配） |
| Q5 | 输入模态焦点 | 无 | 无 | 无 | 安全 |

---

### Q1 — 按需标签：第一个包不加一条，第二个包才长出来

**交互**
- 0 个包：空状态（3 个元素：图标 / "拖入归档 或 Ctrl+O" / 最近 3 条），无标签带。
- 1 个包：**没有标签带**。标题栏 "PrismArchive — fixture.zip"，动作带 top = 32（与今天完全一致）。
- 打开第 2 个包（Ctrl+O / 拖入 / 双击另一个包）：标签带 160 ms 从 0 长到 32，内容**下推**（不淡入、不覆盖）。
- Ctrl+W 关标签；关到 1 个时整条收回，内容上移 32，**滚动位置与选中保持不变**。
- Ctrl+Tab 循环；拖拽重排；脏标记 6 px 圆点。

**视觉**
- 带高 32；标签高 20（上下各 6），宽 clamp 120–224，间距 2，文字内缩 12，关闭钮 16×16 距右 8。
- 活动标签：底 #353A49（现值），底缘 2 px「一线」（§4）；非活动：底同画布，文字 text-secondary。
- 出现时不画阴影、不画分隔线——只靠高度变化和 2 px 线。

**为什么迁移用户不会困惑**
他打开第 1 个包时，屏幕上和 Bandizip 一模一样（树的左边、列表的右边、工具栏在上面）。
第 2 个包时才多出一条，而"我刚刚开了第二个包"这个因果关系是**相邻**的，不需要学习。
对比之下，如果我们一上来就显示标签带，他会在第一秒就要回答一个他没问过的问题："这些是什么？"

**代价（要写进决策记录）**：遮住 32 px 内容、需要一次 160 ms 的布局推挤。
我认为值得，因为收益是"单包用户 0 成本"，这正是迁移漏斗里 90% 的人。

**可跑断言**
- TabSet.size() == 1 → tabBar.Empty()；且 actionIsland.top == titleBar.bottom（差值 0）。
- TabSet.size() == 2 → tabBar.Height() == 32 且 actionIsland.top == titleBar.bottom + 32。
- 关闭第 2 个标签后，列表 scrollOffset 与 selection 与关闭前按字节相等。

### Q2 — 路径尺：把"居中标题"改成"左对齐的尺"

**先说现在的病（这是可量化的，不是审美）**

路径条容器 x 28–718（宽 690），文字 bbox x 234–495（宽 262）。
左边留白 206，右边留白 223，**62.2% 是死空间**，而且**文字左边缘会随路径长度左右移动**——
用户的眼睛没有锚点，读到的是"标题"，不是"路径"。
（同一现象在 c93 截图里也成立：容器 60–750，文字 218–583。）

**交互**
- 每一段可点 = 命中树里对应节点；hover 每段独立高亮，整条不亮。
- 段右侧 8 px 处一个 6×6 chevron（2 px 描边，text-tertiary）。
- 溢出：保留 根 + 末两段，中间折叠成一枚 "…" chip（点开是一列祖先，最多 12 项 + 滚动）。
- 位置条右端：条目计数 "4 项 · 全档 17"，11 px，距右缘 12。
- 键盘：Alt+↑ 上移一级；Backspace 同义（与资源管理器一致）。

**视觉（可直接量）**
- 容器：高度 32，垂直居中于 56 的动作带（上下各 12）；**左缘 = 内容区左缘 + 16**（对齐列表第一列文字，不是对齐窗口边）。
- 段：高 24，左右内边距 8；当前段 600 字重 + text-primary；祖先 400 字重 + text-secondary（现 12.23:1，可安全衰减到 7:1）。
- 当前段下缘 2 px「一线」，长度 = 文字宽 + 8。
- 容器最大宽度 = 动作带宽 − 工具岛宽 − 24；**容器宽度不再固定 690**，它应该跟着内容收，空出来的横向还给工具岛。
- 容器不再是"一整块圆角胶囊装一行居中字"：保持圆角（这是品牌），但内容左对齐、宽度随内容。

**为什么迁移用户不会困惑**
他从来没在 Bandizip 里见过路径条，所以这里**没有"应该长什么样"的预期**——
但他见过资源管理器的地址栏，知道"左边是根、右边是我现在的位置、点一下会跳过去"。
我们只要不把它做成输入框，就是在借用旧心智。

**可跑断言**
- 文字左边缘 − 容器左边缘 == 16（±1 px），与路径长度无关（用 3 条不同深度的路径各测一次）。
- 分段数 == 路径深度，无障碍树里每段一个节点，且每段 Rect 宽 ≥ 24、高 ≥ 24。
- 当前段下方存在连续 2 px 强调色，且路径区只有这 1 处（见 §4.5）。

### Q3 — 状态栏是活的：悬停即预览，不弹窗、不解压

**交互**
- 悬停某一行 → 状态栏左区变成：「img_1.png · PNG · 1.2 MB → 0.9 MB（25%）」。
- 选中 ≥ 1 项 → 变成：「已选 3 项 · 原始 4.6 MB · 压缩后 3.4 MB · 压缩率 26%」。
- 什么都没有 → 回到归档体征（未加密 / 方法 / 字典 / 条目 / 压缩率），与今天一致。
- 40 ms 节流；**任何悬停都只读目录字段，不许触发引擎 I/O 或解压**。

**视觉**
- 复用现有状态栏，不增高、不换位、不换字体（11 px）。
- 左侧字段从 4.59:1 提到 **≥ 7:1**：把 #7A7C82 换成 #A6A6AA（在 #111218 上实测 **7.70:1**）。
- 数值右对齐到同一基线（等宽数字），避免悬停时整段文字左右跳动——这是"安静"的关键细节：
  **文字可以变，位置不能跳**。

**为什么迁移用户不会困惑**
Bandizip 的状态栏本来就在讲"这个包有什么"，我们的只是在同一格里补上"这一项是什么"。
他在资源管理器里早就习惯了"选中文件 → 底部显示大小/日期"。

**可跑断言**
- hover 前后状态栏总宽度不变（±2 px）；字段起点不移动。
- hover 一行的 CPU 时间内不发生引擎调用（用计数器断言：Reader::Read 调用数在 hover 期间 == 0）。

### Q4 — 缩略图预算：先形后影，永远不进折射层

**先说现在的病**
tile 175×283 设备 px（140×226 逻辑），缩略图只有 163×123（130×98 逻辑）→ **图占 tile 面积 40.5%**，其余是空气和一条名字板。
再加上光晕（图块外 50–70 px 泛光），照片区看起来像"没加载完 + 脏"。

**交互**
- 只对 图像/视频 扩展名、且 **压缩后 ≤ 64 MB**、且不在会引发 > 32 MB 寻址的固实体里，才生成缩略图。
- 滚动时每帧最多解码 4 张，滚动即取消；离开视野立刻丢弃（预算优先给可见区）。
- 解码完成 80 ms 交叉淡入（不缩放、不位移、不弹跳）。

**视觉**
- tile 140×145：图 140×105（4:3）+ 名称行 24 + 内边距 8 → **图占 tile 高 72%**（现在 43%）。
- 占位：圆角 8，填充 #FFFFFF06，1 px 边 #FFFFFF14；没有骨架闪条（DESIGN §3 已禁）。
- 缩略图**只画在 tile 矩形内**，不进入任何折射/模糊层——这是光晕的结构性修复，不是调参。

**为什么迁移用户不会困惑**
Bandizip 也有"大图标"视图（工具栏右上角那个 2×2 图标就是它），所以"能看缩略图"不是新概念；
我们只是把它做成可选（列表仍是默认），并且不再把照片糊到背景里。

**可跑断言**
- 相邻两 tile 之间的空隙（本次为 x 637–657、y 291–413，宽 20 px）里，每像素色度（max−min 通道）≤ 10。
  今天该处整条是 #511D1C（色度 53），关折射对照是 #101117（色度 7）。
  注：我最初量的是"tile 外 12 px 环带"，均值 59.15 / 最大 160 —— 那个值把相邻蓝色 tile 也算进去了，
  **不能直接当基线**；断言必须先把相邻 tile 的矩形排除。
- 1000 个图片条目的首屏 TTFF 不因缩略图增加 I/O 调用数（断言 Reader::Read 计数 == 首屏可见非图片条目数）。

### Q5 — 输入模态焦点：鼠标看不见框，键盘永远看得见

**交互**
- 鼠标点选：只出「行底 + 2 px 左缘一线」，**不出焦点内圈**。
- 键盘（方向键 / Tab / type-ahead）：额外 1 px 内圈（#FFFFFF26）+ 2 px 一线。
- type-ahead：500 ms 缓冲，前缀匹配当前排序列；不改变排序、不弹面板、不打字到过滤框。
- "/" 或 Ctrl+F：过滤框从状态栏位置长出来（已有 SearchBoxModel），Esc 清除并**恢复原选中与滚动**。

**视觉**
- 焦点内圈 1 px，距行边 2 px，圆角随行；不发光、不加粗边框。
- 一线在任何输入模态下都只出现在一处（见 §4）。

**为什么迁移用户不会困惑**
"鼠标用户不用看虚线框、键盘用户一定有提示"是 Windows 的既定行为（:focus-visible 语义）；
Bandizip 反而经常在鼠标点击后留下一个虚线框，看起来像没画完。

**可跑断言**
- 鼠标点选后一帧：强调色像素只出现在 2 px 左缘（计数 ≈ 2 × 行高），内圈区域为 0。
- 按一次方向键后：内圈区域出现 ≥ 1 px 的非底色像素。

## 4. 签名设计：「一线」（The Seam）

### 4.1 一句话

**全产品只有一种强调色，只以 1–2 px 的线出现；这条线在哪，你就在哪。**

Bandizip 的记忆点是"蓝工具栏 + 黄文件夹"（面 + 面）。
我们的记忆点应该反过来：**一条线**。在深色玻璃上，面会糊成一片（实测岛与画布只有 1.15:1），
线才是唯一能在 1 px 里表达"层级 + 位置 + 焦点"的东西。

### 4.2 形态

| 属性 | 规格 | 理由 |
|---|---|---|
| 颜色 | 单一令牌：**#0A84FF**（现树选择条用的就是它） | 现状已有 #0A84FF / #0A79EB / #2480DF 三种蓝；统一到最亮的那支 |
| 线宽 | **2 px**（焦点内圈 1 px） | 1 px 在 150% DPI 下会消失；3 px 变成装饰 |
| 出现位置（仅 4 处） | 活动标签下缘 / 路径当前段下缘 / 选中行左缘 / 进度条前沿 | 全部是"当前"，没有一处是"装饰" |
| 长度 | 元素宽 − 24（左右各缩 12） | 让线不和相邻元素粘连 |
| 圆角 | 1 px（线本身） | |
| 静止 | 无渐变、无发光、无尾迹 | 静止时有渐变 = 装饰 |

### 4.3 动效

- 时长 **160 ms**，曲线 cubic-bezier(0.2, 0, 0, 1)（快出慢收，无过冲）。
- 位移 ≤ 320 px 且同轴：线**滑动**并插值长度（"擦除"而不是淡入淡出）。
- 位移 > 320 px 或跨轴：**切断**——80 ms 淡出 + 80 ms 淡入，不飞过去。
  理由：长距离滑动会被读成"动画"，而动画一被注意到，就变成了等待。
- 移动过程中带 24 px 尾迹（100% → 0% alpha，朝运动反方向）；**停下即消失**。
  这是"棱镜"唯一的具象表达：光只在你移动时沿路径走一段。
- 连续按键（40 ms 内）只画终点，不逐行闪。

### 4.4 三个适用场景

**场景 1｜双击进入文件夹**
内容区整体左移 24 px（旧内容），新内容从 +24 px 进入，160 ms；
同时路径尺的一线从旧段滑到新段（如果两段距离 > 320 px，切线不滑）。
为什么是 24 px：小于一个图标宽（16–20），不会造成"换页"的眩晕；大于 0 才有方向感。

**场景 2｜切换标签**
一线沿标签带滑动，长度从旧标签宽插值到新标签宽；标签带本身不位移。

**场景 3｜方向键连续选择**
一线在行左缘上下滑动；若两次按键间隔 < 40 ms，只渲染最终位置。

### 4.5 禁止项（和可跑断言）

禁止：hover 出现一线；同一屏出现两条相距 < 120 px 的一线；用一线做分隔线/装饰下划线；
用一线做品牌渐变；一线出现在滚动条上。

断言（任一稳定状态）：
1. 标签区 2 px 强调色竖/横线计数 == 1（如果标签带存在）。
2. 路径区 == 1。
3. 列表区 == 1（选中为空时 == 0）。
4. 三区之外（工具栏、状态栏）== 0；树有选中时，左缘那条 2 px 也算一线，因此"同一屏两条线"的例外仅限"树 + 列表"这一对（它们相距 > 120 px，允许）。

## 5. 克制清单（"看起来很酷"但我们不该做的 12 件事）

| # | 不做 | 为什么（有数） |
|---|---|---|
| 1 | 全窗 Mica / 亚克力铺满内容区 | 模糊面积一大，内容的锐度就没了；实测光晕把卡片底抬了 ΔL\* 11.9，这就是"大面积模糊"能造成的脏。规则：模糊只给**临时且浮起**的面（HUD、命令面板、右键菜单），面积 ≤ 窗口 15% |
| 2 | 让条目像素进入折射层 | 见上；折射层只取画布 + 面板，不取缩略图（这是 UI-AUDIT §2.2 的根因链，别再用断言把它逼回来） |
| 3 | 动效 > 200 ms、弹性过冲 > 4%、逐项 stagger > 60 ms | 归档是高频重复工具；每次操作多 100 ms，一天 200 次就是 20 秒的"卡顿感" |
| 4 | 彩虹 / 色散渐变 / RGB 描边 | 品牌叫 Prism 不等于 UI 要出彩虹；色散只允许出现在 logo 和"打开中"的那一处高光 |
| 5 | 图标风格化重绘（双色、粗描边、拟物） | 迁移用户靠图标认功能；保持 Win11 线性、1.5 px 描边、16/20 px 两档 |
| 6 | 自动分组 / 智能排序 / "为你推荐" | 列表顺序是肌肉记忆；顺序只能由点击列头改变，且必须显示排序箭头 |
| 7 | 首次运行 tour / 模态引导 / 弹窗式更新日志 | 迁移用户最怕"先学一遍"；教学交给空状态和状态栏 |
| 8 | 滚动条 < 8 px 或自动隐藏 | 大归档需要抓得住；8 px 常显，hover 12 px，拖动时浮出「240 / 1,203」 |
| 9 | 行 hover 抬升 / 缩放 / 投影 | 行不是卡片；hover 只改背景（+6% 白）与 1 px 边 |
| 10 | 页面级 3D / 视差 / 倾斜卡片 | 与"精确定位一个文件"的任务直接冲突 |
| 11 | 自定义光标 / 音效 / 触感反馈 | 无信息量，且会在远程桌面/虚拟机里变形 |
| 12 | 第二条工具栏 / 第二行动作按钮 | chrome 已经 21.4%（Bandizip 22.1%），没有预算；新动作进右键菜单或命令面板 |

## 6. 必须一致 vs 应当超越（一张表，给实现者用）

### 6.1 必须与 Bandizip 一致（动了就是迁移成本）

| 项 | 判据 |
|---|---|
| 左树右表、树宽 220、可折叠 | 位置不动 |
| 双击文件夹进入 / 双击文件智能解压 | 语义不动 |
| 工具栏前 7 键：打开 / 解压 / 压缩 / 添加 / 删除 / 测试 / 查看 | 已同名同序，**不许插新键到它们前面**。第 8 位 Bandizip 是"代码页"、我们是"搜索"——允许不同（代码页不做），但不许把搜索提到前 7 位里 |
| 列表默认 + 四列 + 表头排序箭头 | **列序必须是 名称 / 压缩后大小 / 原始大小 / 类型**。按 c102-day.png 的浅色列表，我们排的是 名称 / 原始大小 / 压缩后 / 压缩率——第 2、3 列**互换了**，这是最容易老用户一眼抓住的"位置不对"（该截图早于当前构建，**需在当前 build 复核**再改） |
| 文件夹金黄 | #FFC83D 家族，不要蓝 |
| 菜单助记符 | Bandizip 是 文件(F) 编辑(E) 查找(I) 选项(O) 视图(V) 帮助(H)；我们只剩 设置(S)，其余五项丢了——至少把 (F)(E)(H) 补回来 |
| 状态栏在底部、高度不增 | 只换文字，不换位置 |
| 空格 = 预览（QuickLook） | 语义不动 |
| 行高密度 | 32 逻辑行高是 Win11 资源管理器的规格，比 Bandizip 的 19.2 高 67%；同样 1007×742 的窗口里，我们 13.2 行 vs 它 21.7 行。**允许不同，但必须给一个 28 的紧凑档**（≈15.0 行），并在窗口高 < 700 逻辑时自动切换，否则小窗口用户第一眼就是"这个软件一屏看不到东西" |

### 6.2 应当超越（差异化，且不新增坐标）

| 维度 | Bandizip | 我们做 | 迁移风险 |
|---|---|---|---|
| 位置 | 无路径，靠树 | 左对齐路径尺 + Alt+↑ + 分段可点 | 低（只读） |
| 会话 | 一窗一包 | 按需标签（≥2 才出现） | 中（唯一新元素，已用"迟到"化解） |
| 主题 | 一套 GDI 浅色 + system-DPI | 跟随系统 + 深浅双主题 + PerMonitorV2 | 低（默认跟随系统即可） |
| 信息 | 状态栏 3 个归档级数字 | 状态栏随悬停/选中变化 + 尺寸不跳 | 低 |
| 媒体 | 有大图标视图，但网格与列表是两套皮 | 同一套 tile 规格 + 缩略图预算 | 低（网格是选配） |
| 焦点 | Win32 虚线框 | 输入模态感知（鼠标无框、键盘有框） | 低 |
| 对比度 | 工具栏 4.50:1 | 正文 ≥ 10:1、次要 ≥ 7:1、禁用 ≥ 1.7:1 | 无（只能更好） |

### 6.3 明确不做（哪怕 Bandizip 有）

- 代码页菜单：它服务的是"解压后文件名乱码"，我们用 UTF-8 自动探测 + 一个"文件名编码"高级选项收纳，不占工具栏
- 大图标工具栏（它把 26 逻辑 px 的图标 + 文字标签铺成 80 逻辑 px 高的一条；我们不复制这个视觉重量）
- 常驻预览面板：预览走空格 QuickLook（浮层、可关），不占一块永远在场的区域

## 7. 如果只有两周：落地顺序

| 顺序 | 事项 | 为什么排这里 | 验收 |
|---|---|---|---|
| 1 | 修光晕（ghost 只承载画布+面板） | 一切"高级感"的前置；现在是负数 | 相邻 tile 间隙色度 ≤ 10 |
