# METHODOLOGY.md — AI agent 研发法：契约先行 + 分层验证

> 背景：当写代码的是 AI agent，瓶颈从"产出代码"转移到**契约、集成、验证与不可并行的 POC**。
> 本会话的量化证据：近 60 次 CI，**50% 失败率**；逐类归因后，约半数失败属于"同类错误重复出现"
> （宏污染、传递 include、窄宽字符串、枚举打印），这些本可以在本地用确定性检查拦下。
> 本文档把经验固化为四套机制：契约治理、验证栈、规则→门禁管线、改造版 TDD。

## 1. 契约治理（详见 CONTRACTS.md）

原则：**契约先于实现存在；没有门禁的契约只是注释。**

四类契约（外部 ABI / 跨层 / 数据所有权 / 验证基建）全部登记台账，每条四要素：
陈述、权威来源、强制门禁、违反案例。

**为什么台账是并行的前提**：给 subagent 的 brief 里可以直接引用编号（"遵守 B1/B2/C5"），
而不是重复叙述上下文。契约不清的并行 = 每个人各自发明约定，merge 时爆炸。

## 2. 五层验证栈（每层的存在理由）

| 层 | 验证什么 | 手段 | 本会话案例 |
|---|---|---|---|
| L1 决策断言 | 纯逻辑对不对 | TDD + 负向控制（突变双编译） | 密码环排序精确顺序断言 |
| L2 真源集成 | 与外部 ABI 的接缝 | **真 7z.dll / 真 WIC / 真 PNG 字节**，绝不 mock 被集成的对象 | S_FALSE bug 只有真 .7z 夹具能暴露 |
| L3 反假绿 | "测试有没有在骗人" | 成功标记入判定（PASS_REGULAR_EXPRESSION）、SKIP=红、**内容断言**（像素颜色/数值/集合） | 0.15s 假 Passed；全零像素放过 |
| L4 环境差异 | 本地≠CI 的隐藏耦合 | **词法/确定性门禁**优先于行为门禁（check_headers 两级） | uint8_t 传递引入只在 CI 炸 |
| L5 证据产物 | 无法自动断言的 POC | 截图/JSON 数字/日志入 artifact，人工或像素校验 | 快照四色检测、Kaggle 冒烟日志 |

**校准规则**：验证工具自身先对已知真值校准（我的 PNG 解析器先对底色验证）；突变必须先
证明"注入发生了"，再谈"测试抓到了"。

## 3. 规则→门禁管线（lessons-to-lint）

每个 CI 失败类必须落地为三件事之一（优先级递增）：
1. **CONTRACTS.md 一行**（最低要求：下次有人读台账）
2. **本地 preflight 检查**（tools/preflight.sh，push 前跑，秒级）——把可 grep 的错误类变成确定性拦截
3. **测试**（错误类可以注入复现时）

已识别的 preflight 检查项（来自本会话的学费清单）：
- `std::min/max/clamp(` 未括号形式（PrismCore 目录）—— B1，≥2 轮 CI
- 用 `u?intN_t` 但无 `#include <cstdint>` —— B2，已自动化
- PrismCore 头出现 `<windows.h>` —— 架构铁律，一条 grep
- 非 UNICODE TU 里 `CFSTR_`/TEXT 宏 —— B5
- `enum class` 所在头无对应 `operator<<` —— B6（启发式）
- 集成测试缺 `PASS_REGULAR_EXPRESSION` 注册而源码含 "SKIP" —— D1

> 估算：本会话 ~30 次失败里约 12 次属此类 ≈ 5-6 个无效 CI 轮次 ≈ 40 分钟纯等待。
> preflight 落地后，同类错误**永不再花一轮 CI**。

## 4. 改造版 TDD：契约先行四阶段

传统 red-green-refactor 在 agent 团队下有三个失败模式：
测试与实现同agent同写 → **同义反复**（测试迁就实现）；
各自本地绿 → 集成红；
测试只断言存在 → 假绿。

**四阶段协议**：

| 阶段 | 谁 | 并行？ | 产出 |
|---|---|---|---|
| ① 契约 | 主 agent（人拍板） | ✗ 不可并行 | 接口头（完整注释：前置/所有权/单位/错误语义）+ 测试骨架（断言来自**规格**而非实现）+ 触到的 CONTRACTS 编号 |
| ② 实现 | subagent（一人一文件域） | ✓ 可并行 | 只写实现，**禁止改测试**；测试错了升级回①，不许改 spec 迁就代码 |
| ③ 突变自证 | 各实现者 | ✓ | 破坏自己的实现→证明测试红；注入必须验证生效（D3/D5） |
| ④ 集成 | 主 agent | ✗ | merge queue：一次合入、全门禁、证据产物 |

②阶段禁止改测试是反同义反复的关键：**测试是规格的执行形态**，实现者对测试的唯一合法
交互是"让它红→写代码让它绿"，或者申诉。

## 5. 并行决策矩阵（什么能派 subagent）

| 类别 | 例子 | 并行性 | 原因 |
|---|---|---|---|
| 新 PrismCore 模块 | SolidSweep/ThumbStore/ListLayout/GlassIsland | **绿** | 契约可先定、零共享状态、Linux 秒级自证 |
| 独立工具/lane | bench harness、preflight、Kaggle farm、PERF 文档 | **绿** | 不碰产品代码 |
| Windows 桥接文件 | 拖拽 IDataObject、DPAPI 补齐 | **黄** | 契约我来定+验收，实现可派；无法本地编译是硬伤（靠 CI 一轮） |
| 契约定义本身 | 接口头、cbuffer 布局、错误枚举 | **红** | 并行定义=两套约定 |
| WinMain 装配 | 消息循环、事件源接线 | **红** | 全是集成点，无独立验证面 |
| 真机 POC | DComp 真渲染、MSIX 真注册、IShellWindows | **红** | 见 §6 |

会话实证：密码环零产出（限流）vs 拖拽收尾成功——差别不在模型，在**任务是否已被契约钉死**。
"收尾到绿"（有现成文件+已知错误）远优于"从零实现"（要自己发明约定）。

## 6. POC 协议（不可并行项的解法）

不可并行 ≠ 不可推进。每个 POC 立项先答四问，写成一行卡：

```
POC-<n>: <名称>
假设 H: <要证明/证伪什么>
证据 E: <最小证据产物（截图/JSON/日志片段）>
采集 A: <怎么自动采（脚本/命令），在哪跑（本地/CI/Kaggle/真机）>
判据 K: <什么算通过，什么算杀死该路线>
```

当前 POC 债（按依赖顺序）：
- **POC-1 DComp+HLSL 真渲染**：H=自定义像素效果经 DComp 岛可视化；E=渲染 PNG+像素断言+FPS；A=CI windows runner 有桌面会话，试 GetDesktopWindow 路线；K=四色 fixture 可见→进主线，不可行→退"模糊+描边"方案（ADR-001 已留后路）
- **POC-2 MSIX 真注册**：H=AddPackageByUriAsync 在 runner 可用；E=注册成功日志+枚举到包；A=windows runner；K=成功→C 批次直通；失败→Inno Setup 备胎
- **POC-3 固实块随机访问解码**：H=7z.dll 可对块内中间条目低成本解码（拖拽 Seek 的基础）；E=延迟表（索引位置 vs 耗时）；A=CI；K=中间条目成本可接受→拖拽通道 B 全速；否则提示用户右键解压
- **POC-4 Kaggle 算力用途**：H= 远端跑得动 p7zip 基准矩阵；E=冒烟已完成（4 核/GitHub 可达）；A=kaggle_farm.py；K=基准数字回流 PERF.md

## 7. 推送纪律（CI 是唯一真裁判，但别浪费轮次）

1. 本地全绿是底线：ctest + check_headers + preflight（建成后）+ workflow YAML 校验
2. **一批次一推送**：把多个独立修复合并成一轮 CI（每次 push 都是一次 7 分钟裁判）
3. 分支模式：solo 分支一律 --force；合并用 PR；main 的 CI 永远是合并后验证
4. 失败日志走单作业端点（run 级 blob 会断），结论必须读注记而不是猜
