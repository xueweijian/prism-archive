# Bandizip 6.29 视觉语言拆解（数值级）

> 采样对象：本机 Bandizip 6.29，打开 `fixture.zip`（12 文件 / 5 目录 / 6 PNG / 2MB bin），
> 截图 `docs/assets/ui/audit-bandizip.png`，1007×742，32bpp。
> 采样工具：PowerShell + System.Drawing，`GetPixel` 逐点读取；所有坐标以截图左上角为原点。
> 原则：只写能复现的数字；推断一律标注「推断」；没采到的态（悬停/焦点/深色）在文末列为未测。

## 0. 先读：坐标系与缩放（否则所有数字都会误读 25%）

截图是 **125% 缩放（120 DPI）**下 1:1 的设备像素。三条独立证据：

| 证据 | 实测 | 96 DPI 应为 | 120 DPI 应为 |
|---|---|---|---|
| 标题栏系统按钮的字形间距 | **59 px**（maximize 一组 911–922，close 一组 970–981） | 46 px | 57.5 px |
| 9pt 中文的墨迹高（菜单「文件」） | **13 px** | 10–11 px | 13 px |
| 列表行距 / 工具图标 / 工具栏高 | **24 / 20 / 100 px** | 19 / 16 / 80 | 19.2 / 20 / 100 |

结论：**逻辑像素 = 设备像素 ÷ 1.25**。下文每个尺寸都给「设备 px（图内坐标）」与「逻辑 px（设计值）」。

文字用 GDI ClearType 渲染，笔画边缘有 RGB 亚像素彩边（实测出现 #B66600、#0066B6、#DBFFFF 一类），
所以取色只取笔画芯（正文芯色 = **#000000**）。

## 1. 色板

### 1.1 工具栏蓝：不是自定义品牌色，是 **#0078D7 + 一层 36% 白光泽**

这是全篇最关键的发现。工具栏不是一个纯色，也不是简单的上下渐变：

| 角点（采样坐标） | HEX | RGB | 说明 |
|---|---|---|---|
| 左下 (30,162) | **#0078D7** | 0,120,215 | 纯 Windows 强调蓝 |
| 左上 (30,63) | #1B86DA | 27,134,218 | |
| 右下 (1000,162) | #1A85DA | 26,133,218 | |
| 右上 (1000,63) | **#5CA8E4** | 92,168,228 | 最亮角 |
| 中部 (500,100) | #2289DB | 34,137,219 | |

- **#0078D7 + 36% 白 = (92,169,229)**，实测最亮角 (92,168,228)，误差 1。→ 光泽就是一层白色叠加。
- 方向：**近乎垂直、向右倾约 6°**。拟合 `R ≈ 0.067·x − 0.657·y + 66.4`（8 个采样点，最大残差 6/255）。
  竖直方向每 px 变化 0.66 个 R，水平方向只有 0.067 —— 所以肉眼读成「上亮下暗」，但右半边整体更亮。
- 光泽在左下角被裁剪：y=155 时 x<463 全是纯 #0078D7（R=0）。

**代价（见 1.3）**：同一排 8 个按钮，白字对比度从最左 4.50:1 一路降到最右 3.75:1。

## 3. 图标语言

### 3.1 工具栏：32px 白线稿，**不填充、双页叠放、直角**

把 (25,80)–(68,126) 放大成 ASCII 后可以直接数出来：

- **线宽 1 逻辑 px**：每条边是「1 px 实心 + 1 px 抗锯齿」（如 `#+`），不是 2px 粗线。
- **圆角 0**：四个角是直角，所谓「圆」只是 AA 产生的 1px 视觉软化。
- **构图**：打开 = 后页 + 前页 + 右箭头；解压 = 后页 + 拉链页 + 右箭头；新建 = 两页叠放；
  添加/删除 = 单页 + 居中 +/−；测试 = 闪电；查看 = 三线清单；代码页 = 地球。
- **风格 = 纯线性、单色白、零填充、零双色**。这是 VS2005 / Office2007 前后工具栏的典型做法。
- **网格**：图标没有外框，像素读不出画布；8 个图标墨迹集中在 25–34 × 30–36 逻辑 px，按 Windows 工具栏惯例推断画布为 32×32，图形上下可出血。
- **下拉箭头是独立小件**：8×6 px 的 V 形，画在图标右侧 35 px 处（打开：图标 27–65，chevron 98–105）。

### 3.2 列表 / 树：16px 彩色位图

- 文件夹：16×16 位图，金黄渐变 + 深金描边（#FFE9A8 → #FFCF4C → #E9AE1C），带左上 tab。
- 文件：按类型给图标（data.bin 蓝圆闪电、readme.md 白纸折角），主色统一 #0078D7。
- 树：同样是 16×16 彩色位图；可展开节点前加 1px 灰 chevron（#808080 系），每级缩进 8.8 逻辑 px。
  **子目录也有文件夹图标**（实测每一行 x=29–46 都有金黄像素）——
  这一点与 `docs/UI-AUDIT-BANDIZIP.md` 第 3 节「只有归档节点有图标」的结论**相反**，以像素为准。

### 3.3 两套语言并存的代价

工具栏是 **白线稿**，内容区是 **彩色位图**。2007 年这是标准搭配，今天的问题有两条：

1. 32px 位图在非整数倍缩放（150%）下会被重采样，1px 线糊成 2px 灰边（本轮只测 125%，此为通用推断）；内容区 16px 图标是另一套栅格，两套无法共用。
2. 线稿靠「白色 + 蓝底」维持可见性；一旦底色变亮（渐变右侧 3.75:1），1px 线就接近消失 ——
   代码页的地球在亮部只剩轮廓感。

## 4. 排版

**全文只有一个字号、一个字重、一种文字色。**

| 部位 | 字体（视觉判断） | 字号 | 字身 | 字重 | 颜色 | 行高 |
|---|---|---|---|---|---|---|
| 标题栏 | Segoe UI | 9pt | 15 px | 400 | #000000 | 37 |
| 菜单 | Segoe UI / 微软雅黑 | 9pt | 15 px | 400 | #000000 | 23 |
| 工具栏标签 | 微软雅黑 | 9pt | 15 px | 400 | #FFFFFF | 13（墨迹） |
| 表头 | 微软雅黑 | 9pt | 15 px | **400（非粗体）** | #000000 | 27 |

| 状态栏 | 微软雅黑 | 9pt | 15 px | 400 | #000000 | 34 |

要点：

- 字身 15 设备 px = 12 逻辑 px = **9pt**（125% 缩放）。用墨迹反推：中文 13 px、西文 12 px（含升部）。

- 没有 12px 辅助文字、没有 #666 次级色、没有两级标题 —— **层级完全由位置和底色承担**。
- 行距：列表 24/15 = **1.6**；树 22/15 = **1.47**；菜单项横向节距 52.8 逻辑 px。
- 助记符齐全：文件(F) 编辑(E) 查找(I) 选项(O) 视图(V) 帮助(H)。

## 5. 它为什么「看起来像 2007，但依然好用」

### 5.1 做对的 5 条（都能落到数字）

1. **密度**：19.2 逻辑 px 行高 + 9pt 字，一屏 395 逻辑 px 放得下 **20 行**；1007 px 宽塞 4 列。
   对照 PrismArchive 的网格（3 张 165×280 的卡片只表达 3 个文件夹），同一屏信息量差 3 倍以上。
2. **位置恒定**：菜单 38 → 工具栏 63 → 表头 164 → 状态栏 706。任何一次打开、任何一个包，四段腰线都在同一坐标。
   迁移成本几乎为零，因为「手往哪放」不需要重新学。
3. **图标必配文字**：8/8 按钮都有 13px 中文标签；不认识的图标（闪电=测试、地球=代码页）也能读。
   这是「可预期性」最便宜的实现方式。
4. **状态诚实**：选中 = 灰底 + 1px 框（14.88:1），排序 = 明确的小箭头，状态栏报「文件 / 文件夹 / 压缩包大小」三个可核对数。
   没有隐藏态、没有只靠颜色表达的状态。
5. **零动效、零阴影、只有 3 种材质**：白 #FFFFFF、灰 #F0F0F0、蓝 #0078D7。
   渲染成本低、认知成本也低 —— 眼睛不需要重新解析任何一层。

### 5.2 过时的 5 条（也都能落到数字）

1. **纯黑 21:1 + 无深色模式**：正文 #000000 on #FFFFFF，夜里刺眼；整张图没有任何深色痕迹。
2. **渐变吃掉可读性**：白字在右半段 3.75:1、最亮角 2.57:1，同一排按钮出现两种可读性标准。
3. **位图图标 + 1px 发丝线**：非整数倍缩放下发虚（推断，本轮只测 125%）；文件夹是 Win7 金黄位图，与 Win11 Fluent 图标并置有「代沟」。
4. **3px 滚动条滑块**（3.24:1、无箭头、无悬停反馈）：现代覆盖式滚动条至少 8–12px 厚 + 44px 命中区。
5. **表头与正文同为 #FFFFFF、无底边**：边界只靠列线从 #E5E5E5 变 #EBF4FE（1.26:1 → 1.11:1）暗示；
   且类型列被窗口右缘裁掉（129 px 装不下「Markdown 源文件」），必须横向滚动。

补充一条不算缺点、但不建议照抄的：**排序箭头被放在名称列水平正中、表头顶沿**（x=435–443，列中心 438），
而 Explorer 的惯例是贴列右端、垂直居中。这是 Bandizip 自己的表头习惯，迁移用户大概率会去列右端找它。

## 6. 一句话总结：它的设计基因

**2003 年 Explorer 的四段骨架 + 2007 年的一张蓝色渐变皮肤：颜色只用来分区，文字只用来报事实，位置永远不变。**

拆成可执行的三条：

- **骨架**：菜单/蓝条工具栏/树+四列列表/状态栏，四段腰线固定；
- **皮肤**：只有一条渐变（#0078D7 → +36% 白），三种材质（白/灰/蓝），零圆角零阴影；
- **语法**：9pt 单字号单字重，图标必带文字，状态必须能被数字核对。

| 四段骨架与高度 | 菜单 18 / 工具栏 80 / 表头 21.6 / 行 19.2 / 状态栏 27.2 | 腰线位置 = 肌肉记忆 |

| 树结构 | 归档 + 目录，行高 17.6，缩进 8.8，每级 16px 图标 | |
| 菜单助记符 | (F)(E)(I)(O)(V)(H) | 键盘用户 |

### 7.2 应当超越（差异化，且每条都能验收）

| 项 | Bandizip 现状 | 建议值 | 验收数字 |
|---|---|---|---|
| 工具栏蓝 | 渐变 0→36% 白，白字 4.50→3.75:1 | 纯色 **#0F6CBD**；要层次就做暗向渐变 #0067C0 → #0F6CBD，**不要白光泽**（12% 白已把对比度拉到 3.60:1） | 白字 **5.38:1** ≥ 4.5，全条 ≥ 5.0 |
| 正文色 | #000000（21:1） | **#1A1A1A** | 17.40:1（仍远高于 AA，夜间更柔） |
| 表头边界 | 无底边、与正文同白 | 底 **#F1F4F8** + 1px **#D0D7DE** 底边 | 底/正文 1.10:1，线/底 1.32:1（可测，且在 100% 缩放下不糊） |
| 选中行 | #D9D9D9 灰 + #949494 框 | **#0F6CBD 底 + 白字** | 5.38:1 |
| 滚动条 | 滑块 2.4 逻辑 px 厚 | ≥8 px 厚、悬停 12 px、命中 44 px | 命中区 ≥ 44×44 |
| 图标 | 32px 位图 + 1px 发丝线 | 矢量、1.5px 描边、与 16px 彩色图标共用 4px 网格 | 150% 下无重采样灰边 |
| 列宽 | 固定 300/99/99，末列被裁 | 自适应 + 末列不裁 | 1007 px 宽下四列完整可见 |

### 7.3 明确不要照抄

- 3px 滚动条滑块；21:1 纯黑正文；用渐变做「高级感」而牺牲对比度；
- 无底边的表头；居中的排序箭头（放回列右端）；
- 工具栏右侧 141 px 的空白（那是按钮左对齐、不拉伸的副产品）。

## 附录 B：复现

在装有 Bandizip 的机器上截同一窗口，然后用 PowerShell + System.Drawing 逐点取值：

    Add-Type -AssemblyName System.Drawing
    $bmp = [System.Drawing.Bitmap]::FromFile('...\audit-bandizip.png')
    $c = $bmp.GetPixel(1000, 63)   # 右上角 -> #5CA8E4
    '{0:X2}{1:X2}{2:X2}' -f $c.R, $c.G, $c.B

对比度用 WCAG 相对亮度公式：对每个通道 c/255 ≤ 0.04045 ? c/12.92 : ((c/255+0.055)/1.055)^2.4，
L = 0.2126R + 0.7152G + 0.0722B，比值 = (L1+0.05)/(L2+0.05)。
