# 设计提案：让 Bandizip 用户零负担地换过来，并且更好看

> 2026-11-07。**只做设计判断，不改代码。**
> 依据：`docs/UI-AUDIT-BANDIZIP.md` 的两轮实测（同一 `fixture.zip`，Bandizip 6.29 vs 本机安装版），
> 以及下面这些**实测数字**（像素采样 / A/B 对照）。

## 【前置】在讨论任何设计之前：这个程序是 DPI-UNAWARE 的

> 2026-11-07 实测（探针命令见 `E:\Temp\design\E-platform-fusion.md` 第 9 节）。

| 证据 | 结果 |
|---|---|
| exe 内嵌 manifest | 只有 `<trustInfo>/asInvoker`，**无 `dpiAware` / `dpiAwareness`** |
| `Src/` 全树 grep | **无** `SetProcessDpiAwarenessContext` / `SetProcessDPIAware`（命中只在 `Tests/win/`） |
| `GetProcessDpiAwareness`（CREATE_SUSPENDED 进程） | `hr=0, value=0` → **UNAWARE** |
| 本机 `LogPixels` | **120**（125%） |

**后果**：整窗按 96 DPI 渲染 → 系统 1.25× 双线性放大 → **所有文字与 1px 线条都是糊的**。
截图 1732×1011 = 1385.6×808.8 DIP × 1.25，这正是为什么"看起来不够锐"。
各处对话框里的 `WM_DPICHANGED` 分支**是死代码**（进程 UNAWARE 时永远不会收到）。

> **这意味着：本提案后面所有关于 1px 描边、4px 栅格、30px 行高的讨论，
> 在 DPI 修好之前都无法被用户看到。**
>
> **修法：manifest 加一行 `PerMonitorV2`。这是整个项目 ROI 最高的一行代码。**

### 另外三条同样属于"前置"的平台事实

| # | 事实 | 影响 |
|---|---|---|
| 1 | **"跟随系统"是假的**：`ShellVariantFor("system")` 直接返回 Midnight，且有测试钉死这条 | 本机系统是**浅色**，Bandizip 白底，**我们给黑** —— 迁移语境下最贵的一条 |
| 2 | 本机 `EnableTransparency=0`（透明效果关闭） | 任何以 Mica 为唯一层级手段的方案会退化成实色；**必须设计 solid fallback** |
| 3 | 画布是**不透明 Clear** | 即使设 `DWMWA_SYSTEMBACKDROP_TYPE` 也看不见 |

### 平台缺口清单（逐条 grep 证据）

| 缺口 | 后果 |
|---|---|
| 无滚动条绘制（0 命中） | 滚动条是系统绘制的，与自绘 UI 风格割裂 |
| 列表/树**无焦点环**（只有动作条 2 DIP 环） | 键盘用户不知道焦点在哪 |
| 无 `NotifyWinEvent` / UIA 事件 | **选中变化读屏无感知** |
| 无 `CreateAcceleratorTable` / `TranslateAccelerator` | 菜单快捷键靠手写消息处理 |
| 无 `WM_SETTINGCHANGE` | 系统换主题/换 DPI 时**不响应** |
| 无 `SPI_GETHIGHCONTRAST` | 高对比度模式**不生效** |
| 无 `ImmSetCandidateWindow` | **中文输入候选框落在系统默认位置**（不在输入框旁） |
| 无 `SetCurrentProcessExplicitAppUserModelID` | 任务栏图标分组不正确 |
| 窗口位置只存 w/h | 下次打开**位置丢失** |

### 一条"我们其实更好"的数字（别为了对齐往回调）

| | 动作条标签对比度 |
|---|---|
| 我们 | **14.15 : 1** |
| Bandizip 工具栏最暗端白字 | **4.32 : 1**（低于 4.5） |

### 落地顺序（E 建议，我同意）

1. **manifest 加 PerMonitorV2**（一行，消掉全部糊）
2. `WM_SETTINGCHANGE` + "跟随系统"真的跟随
3. 高对比度自动降级
4. `NotifyWinEvent` + 列表/树焦点环
5. `ImmSetCandidateWindow`

## 0. 核心诊断：不是细节不够，是**品类错位**

Bandizip 是**文件管理器**：信息优先、密集、可预期、几乎没有装饰。
PrismArchive 现在是一个**画廊应用**：网格优先、大卡片、浮动玻璃、留白很多。

> 用户说"不像 Bandizip"，本质是**你给他的第一屏是另一个品类的东西**。
> 把所有细节打磨到极致，只要第一屏还是"三个大文件夹卡片 + 浮动岛"，它就仍然不像。

**所以本提案的第一条不是"更好看"，是"先成为同一个品类，再在这个品类里做到最好看"。**

## 1. 五条设计原则

| # | 原则 | 一句话解释 |
|---|---|---|
| P1 | **信息先于装饰** | 一屏能看到的条目数，是文件管理器最重要的"美观"指标 |
| P2 | **材质只在窗框** | 玻璃/亚克力只用在**内容不会从下面滚过**的地方；内容区永远实色 |
| P3 | **一个强调色** | 强调色只用于「选中 / 焦点 / 主按钮」，其余靠明度层次 |
| P4 | **肌肉记忆优先** | 位置、快捷键、动词顺序与 Bandizip 1:1；创新只放在"可选"位置 |
| P5 | **安静的动效** | ≤120ms，只做透明度与 8px 位移；不做弹跳、不做全屏模糊 |

| 信息卡 | 无 | 左下四组（我们的特色） |

### 2.4 一个必须修的缺陷：**光晕**

A/B（只切 `backdropRefraction`）：开 → 每张照片周围一圈模糊彩色光晕；关 → 干净。
像素测量：红色照片包围盒 163×123，与图块同宽 —— **图块没溢出，光晕来自内容带的玻璃层把缩略图模糊进了背景**。

根因：C110 为了让 C77-1（"这层真的在折射内容"）保持绿，在 ghost 里保留了缩略图。
**一条断言在逼出视觉缺陷。**

| 区域 | 材质 | 理由 |
|---|---|---|
| 标题栏 / 工具栏 / 状态栏 | **玻璃（静态背景模糊，每帧最多算一次）** | 内容不会从下面滚过 |

## 5. 组件规格

### 5.1 工具栏（贴边，56px）

- 分组：`打开▾ 解压▾` │ `新建 添加 删除` │ `测试 查看` │ 右端 `视图切换 / 搜索`。
- `打开`/`解压` 带**下拉箭头**（Bandizip 有；这是高频操作的分支入口）。
- 主按钮：`解压` 用强调色实心，其余用图标+文字（hover 出 6% 白）。
- 禁用态：40% 不透明度 + 保持布局（不塌陷）。

### 5.2 面包屑（28px，一条路径）

- 形态：`fixture.zip › photos › 2026`，段间 `›` 12px 次要色。
- hover：当前段出现 6% 白胶囊（圆角 6），**不做浮动岛**。
- 溢出：中间段折叠成 `…`，首尾永远可见。
- 无障碍：**每段一个节点**（现状是一个整体，读屏和自动化点不到）。

### 5.3 列表（默认视图）

- 四列：`名称`（弹性）`压缩后大小`（120，右对齐）`原始大小`（120，右对齐）`类型`（100）。
- 表头：11px 次要色，hover 出排序箭头，点击切换。
- 行：30px；选中 = 强调 10% 填充 + 2px 左条；hover = 4% 白。
- 图标：16px，文件夹暖金黄，文件按类型（文档/图片/代码/二进制/未知 五类即可）。
- **斑马纹不要**（Bandizip 没有，我们也别加）。

### 5.4 树（260px）

- **每个目录都有图标**（与 Bandizip 同构）；图标改**金黄**，展开器 16px、hover 才显形。
- 选中：强调 10% 填充 + 2px 左条。
- 展开器 16px，hover 才显形。

### 5.5 状态栏（28px）

- 左：`文件: 12   文件夹: 5`；中：`压缩包大小: 2.00 MB`；右：`压缩率 98.8%`。
- 加密/方法/字典**移入信息卡**（我们已有），不占状态栏。

### 5.6 信息卡（保留，我们的特色）

- 位置不变（左下），但**改为可折叠**，默认折叠成一行 `🔒 未加密 · ZIP · 98.8%`，点击展开四组。
- 理由：Bandizip 没有它；默认展开会让第一屏更"重"。

## 7. 三个"安静的签名"（超越点，不增加学习成本）

### 签名 1：**可点的路径条**
Bandizip 没有面包屑。我们把它做成一条**清晰的路径**，点击任意段跳转。
迁移用户不需要学——它就是"路径"的直觉形态。

### 签名 2：**空格即时预览**
选中文件按空格，右侧滑出 380px 预览面板（图片/文本/PDF 首页），再按空格关闭。
Bandizip 的"查看"是外部打开；我们给"看一眼"这个动作一个更轻的答案。
**默认不影响布局**（面板浮在列表右侧，列表宽度不变）。

### 签名 3：**安静的玻璃**
只有窗框有材质，且随主题呼吸；内容永远实色。
用户的感受是"这个窗口很贵"，而不是"这个界面很花"。

## 12. 像素级实测补充（第三方诊断，2026-11-07）

### 12.1 光晕的物理模型（不是"柔光"，是低分辨率块被放大）

```
0.35 × (210,60,50) + 0.65 × (12,13,17) = (81,29,29)   模型
实测环带                              = (81,29,28)   ✓
```

| 量 | 开折射 | 关折射 | 倍数 |
|---|---|---|---|
| 图块右侧 8–16px 环带色度 | 49.9（SD 4.3） | 7.0（SD 0.0） | **7.1×** |
| ΔE76 vs 画布 | 30.5 | 2.4 | **12.7×** |
| 扩散半径 | **46–48 lp**（图块间隙 13px 的 4.4 倍） | — | 三张照片在缝里连成一片 |
| 污染面积 | **≈2.26×10^5 px = 内容区 21%** | 0 | |

**副作用**：开/关折射时画布本身 `(16,17,23)→(12,13,17)`，ΔE 2.4 —— **玻璃层不是色度中性的**。

### 12.2 表面层级无序：11 个色调，主次颠倒

| 对比 | 对比度 | 问题 |
|---|---|---|
| 动作岛 vs 画布 | **1.15** | 最该"响"的主操作区反而最轻 |
| 侧栏 vs 画布 | **1.32** | 最响的是侧栏 |
| 卡片 vs 列表行 | ΔE **0.5** | 完全不可分（(26,27,30) vs (27,28,31)） |

### 12.3 一屏两套几何、两套节奏

| 量 | 网格 | 列表 |
|---|---|---|
| 单元尺寸 | 卡片 163×240 + 名牌 163×36（宽高比 0.68 竖长） | 行 1412×40 |
| 间隙 | 13px | 3px |

- 行/卡宽度比 **8.66 : 1**；间隙差 **4.3 倍**；缩略区↔名牌缝 **1px**；
- 右缘三值不一致：岛 **1698** ≠ 行 **1709** ≠ 内容 **1710**；
- 照片只占卡片 **50.1%**（另一半是信箱空带）；文件夹图标占 **16.3%**；
- 密度：我们 **214,080 px²/条目** vs Bandizip **108,756** → **松 1.97 倍**。

### 12.4 排版与对比度的真相

- **实际只有 3 档墨高**（7.2 / 10.4 / 16 lp），规格写的 4 档（11/13/15/20）未落实，13 与 15 合并；

- 对比度：面包屑 **17.7:1**（与内容同亮 → 无层级）、内容 17.7、状态栏 5.52、信息卡标题 6.93、**窗口标题 3.77（不达 AA）**。

### 12.5 一色三义

文件夹 `#2480DF`、强调色 `(10,132,255)`、选中底 `(33,53,80)` —— **同处 210–214° 色相**。
用户无法从颜色判断"这是可点的强调，还是文件夹，还是选中"。

对照 Bandizip 的金：主体 `(255,182,102)` / 高光 `(255,219,144)` / 暗边 `(219,144,58)`，
**对白底仅 1.61:1** —— 它是**材料色**，不抢注意力。这正是"文件夹金黄"为什么好用：它足够识别，又足够安静。

## 13. 两位研究者的实测修正（2026-11-07 晚）

### 13.1 【重要】Bandizip 截图的 DPI 前提

`audit-bandizip.png` 是 **125% DPI 的 1:1 设备像素**，**逻辑 px = 设备 px ÷ 1.25**。
三条独立证据：系统标题按钮字形间距 59px（96dpi 应为 46）；9pt 中文墨迹高 13px；行高 24 / 图标 20 / 工具栏 100 全是 1.25 的整数倍。

**此前所有直接拿这张图量出来的尺寸都偏大 25%**，本提案已按逻辑 px 修正。

### 13.2 Bandizip 的真实骨架（逻辑 px）

| 部位 | 逻辑 px |
|---|---|
| 菜单 | 18.4 |
| 工具栏 | **80** |
| 表头 | 21.6 |
| **行高** | **19.2** |
| 状态栏 | 27.2 |
| 树宽 / 树行 / 缩进 | 195.2 / 17.6 / 8.8 |
| 四列宽 | 300 / 99 / 99 / ≥103 |

> **修正**：本提案第 4.3 节写的"列表行高 30"是按错误前提定的。
> Bandizip 实际 **19.2**（比 Win11 Explorer 的 32 密得多）。
> **建议取 26**：比 Bandizip 松 35%（现代 HiDPI 更舒适），比 Win11 Explorer 紧 19%（保住"文件管理器"的密度感）。
> 26 是"像 Bandizip 但不挤眼"的折中值；若目标是极致密度，取 22。

### 13.3 工具栏蓝的真相：`#0078D7` + 36% 白光泽

Bandizip 的蓝不是品牌色，是 **`#0078D7` 叠一层 36% 白光泽**（最亮角 `#5CA8E4`，误差 1/255），
渐变近垂直、右倾约 6°。

**代价**：白字对比度从最左 **4.50:1**（刚好压 AA 线）掉到中部 4.12、右部 3.75、最亮角 **2.57** ——
同一排按钮出现两种可读性。

> **不要照抄光泽。** 用**纯色** `#0F6CBD`：白字 **5.38:1**（稳过 AA），且深色主题下同一色相可复用。

### 13.4 Bandizip 的排版：只有一个字号、一个字重、一种文字色

全 UI：**9pt / 400 / #000000**。表头不加粗、不变色、不加底，层级**只靠位置和底色**。

对照我们：3 档墨高（7.2 / 10.4 / 16 lp）+ **只有一档字重**。
也就是说我们"想分层却没分出来"，而 Bandizip"不分层却很清楚"。

**建议**：3 档字号（11 / 13 / 15）+ **2 档字重**（400 / 600，只给表头与标题），不要再加字号。

### 13.5 Bandizip 没有的东西（我们也别加）

- **没有斑马纹**、**没有行线**（纯白底 + 位置）；
- 没有深色模式；
- 表头无底边、末列被裁（这是缺陷，别学）；
- 滚动条滑块仅 **3px**（命中 2.4px）—— 我们要 ≥8px 厚、≥44px 命中。

### 13.6 修正后的"必须一致 / 应当超越"分割

| 必须一致（迁移成本） | 应当超越（差异化） |
|---|---|
| 四段腰线高度（菜单/工具栏/表头/状态栏） | 工具栏**纯色** `#0F6CBD`（不抄光泽） |
| 工具栏贴边 + 32px 图标 + 标签 | 正文 `#1A1A1A`（17.4:1） |
| 四列 + 两个数值列右对齐 | 表头 `#F1F4F8` + `#D0D7DE` 底线 |
| 金黄文件夹 `#FFCF4C` / 描边 `#E9AE1C` | 选中 `#0F6CBD` + 白字 |
| 树 17.6 / 缩进 8.8 | 滚动条 ≥8px 厚 / ≥44px 命中 |
| 助记符 | 矢量 1.5px 描边（不用位图） |
| | 末列不裁 |

## 14. 迁移心理学的实测修正（第三位研究者）

### 14.1 【危险】F5 不是解压

运行时菜单实读（`GetMenuStringW`，Bandizip PID 9924）：

```
选项(O) → 设置(&S)    F5        ← F5 = 设置，且是"选项"菜单的唯一一项
文件(F) → 解压文件(&E) Ctrl+E   ← 解压在这里
```

> 本提案第 6 节原来写「F5 = 解压」是**错的**。
> 若按错的那样实现，老用户想改设置会触发解压 → **12 个文件被写盘**。
> **这是不可逆副作用，必须在实现前钉死。**

### 14.2 【更危险】Ctrl+E 同键不同后果

| | Bandizip | 我们（`Shortcuts.hpp`） |
|---|---|---|
| `Ctrl+E` | **弹解压对话框**（可取消） | **SmartExtract：静默写盘** |

**建议**：`Ctrl+E` 必须弹对话框；静默解压挪到 `Ctrl+Alt+E`（或干脆取消静默路径）。

### 14.3 快捷键对账（13 个主键）

| 结果 | 数量 | 键 |
|---|---|---|
| 一致 | 4 | `Ctrl+O` `Ctrl+F` `F2` `Del` |
| **语义冲突** | 2 | `Ctrl+E`（对话框 vs 静默写盘）、`Ctrl+Shift+N` |
| **空绑定** | 7 | `Ctrl+N` `F4` `Ctrl+T` `Ins` `F5` `Ctrl+W` `Ctrl+C/V` |

> 全仓 grep **无 `VK_F5` / `VK_F3`** —— F3/F5 确实完全没绑。

### 14.4 【最贵的空间数字】"打开"按钮偏了 611px

（125% DPI，逻辑 px = 设备 ÷ 1.25）

| 量 | Bandizip | 我们 | 差 |
|---|---|---|---|
| 「打开」按钮中心 | **(32, 83)** | **(643, 138)** | **横向偏 611 px** |
| 工具栏顶边 | 50 | 117 | 67 |

**根因不是美术，是结构**：标签条（79 设备 px）+ 面包屑（700×67）把工具栏**挤到了内容区上方**，
于是它从 x=736 开始，**不是通栏**。

**修法（结构级，不改美术）**：
1. 标签页塞进标题栏；
2. 面包屑降到 ≤28 高并下移一行；
3. → 工具栏可回到 **y≈64**，与 Bandizip 同一行、通栏。

### 14.5 其它对账

| 项 | Bandizip | 我们 |
|---|---|---|
| 行距（逻辑 px） | **19.8** | **31.6**（+60%） |
| 每 100px 可见行数 | 5.05 | 3.16（**−37%**） |
| 菜单项 | 6 项（含 查找(I) / 视图(V)） | 4 项（**缺这两项**；「选项(O)」被改名「设置(S)...」并前移到第 3 位） |
| 禁用态对比度 | 8 个按钮全亮 | 「添加/删除」= `#4A4D54` on `#1A1D25` = **1.99:1**（应 ≥3:1） |

### 14.6 两个数字的信任问题

同屏出现 **状态栏「条目 5」** 与 **面包屑「全档 17」** —— 用户会问"到底几个？"。
建议统一口径：状态栏显示"当前目录 5 / 全档 17"。

### 14.7 反模式（我们犯了 11 条中的 9 条，摘要）

- 把**未实现**显示成"未知"（方法未知 / 字典未知）→ **未知字段不渲染**；
- 默认视图与目标用户习惯相反；
- 主操作不在第一位置；
- 同屏两套几何；
- 材质盖内容；
- 禁用态不可读；
- 快捷键同键不同后果；
- 两个口径的数字同屏；
- 用"创新"换掉肌肉记忆。

## 16. 归一化修正：别拿两个不同尺寸的窗口比绝对像素

（第五位研究者）两个窗口尺寸不同：Bandizip **1007×742**，我们 **1732×1011**。
直接比绝对像素会夸大差异，必须**按占窗口高度的百分比**归一化。

| 维度 | Bandizip | 我们 | 结论 |
|---|---|---|---|
| 顶部 chrome 结束 | y=164（**22.1%** 窗高） | y=216（**21.4%**） | **我们并不更臃肿** |
| 内容区高度 | 521 px（70.2%） | 761 px（75.3%） | 我们给内容更多 |
| 列表行节距 | 24 px（**3.23%**） | 40 px（**3.96%**） | 相对高 **22%** |
| 一屏可见行 | ≈21.7 | ≈19.0 | **−12%**（不是 −37%） |

> 前一节引用的"−37%"是按绝对像素算的，**在归一化后不成立**。
> 正确的说法是：**我们的行相对高 22%，一屏少 12%** —— 可感知，但不致命。
> 行高目标仍是 26 逻辑 px（介于 Bandizip 19.2 与 Win11 32 之间）。

### 16.1 三个蓝在抢同一个角色

| 用途 | 色值 |
|---|---|
| 选择条 | `#0A84FF` |
| 标签下划线 | `#0A79EB` |
| 文件夹填充 | `#2480DF` |

**一个产品只需要一个强调色。** 统一它们本身就是一次"看起来变贵了"的升级，**零学习成本**。

### 16.2 其它归一化后的数字

| 项 | 值 | 判断 |
|---|---|---|
| 状态条文字对比 | **4.59:1** | 刚过 AA，**没有余量** |
| 树选中底对比 | **1.18:1** | 太弱 |
| 禁用项对比 | 1.79:1 | 可接受（禁用豁免），但接近看不见 |
| Bandizip 状态条对比 | **21:1** | 纯黑/纯白，这是"可读性"的基线 |

### 16.3 签名设计：**"一线"（The Seam）**

全产品只有**一条 2px 强调线**，它在哪，你就在哪。
用途：选中行左条、当前标签下划线、焦点环、面包屑当前段——**同一个视觉元素，四种语义位置**。

为什么是它：
- 零学习成本（用户不需要理解新概念，只需要"跟着线走"）；
- 把现在三个蓝收敛成一个，**同时解决"一色三义"**；
- 在深色和浅色下都成立；
- 它是**位置语言**，不是装饰。

### 16.4 铁律（D 提出，我采纳）

> **不新增面板、不新增工具栏、不新增模态框。**
> 谁想加，先证明它**不占新的坐标**。

这条直接约束我们自己：Quick Look 面板只能浮在**已有**的列表右缘，不能改变列表宽度；
信息卡只能**折叠**，不能变高。
## 17. 最后的校准（第五位研究者补充）

### 17.1 两个"少多少行"的答案都对，取决于基准

| 基准 | 我们 | Bandizip | 差 |
|---|---|---|---|
| 各自窗口（1732×1011 vs 1007×742） | 19.0 行 | 21.7 行 | −12% |
| **同样 1007×742** | **13.2 行** | **21.7 行** | **−39%** |

**结论**：小窗口用户第一眼就是"一屏看不到东西"。
**对策**：提供 **28 逻辑 px 紧凑档**（同尺寸下 15.0 行），并在**窗口高 <700 逻辑 px 时自动切换**。

### 17.2 标签"迟到"：1 个包不占像素

现状：只要有归档就显示标签带（占 32px 高）。
**改**：**≥2 个包才出现**标签带；1 个包时 0 像素 chrome。
理由：迁移用户第一次打开只有一个包，此时标签带是纯成本。

### 17.3 面包屑现在是"居中"的，浪费 62% 空间

实测：容器 28–718，文字 234–495 → **62.2% 死空间**，且**左缘随路径长度漂移**。
**改**：左对齐到内容区 +16，段可点，当前段下缘 2px 一线。

### 17.4 缩略图预算

| | 现在 | 建议 |
|---|---|---|
| 图块 | 175×283 | **140×145** |
| 图片占高 | 40.5% | **72%** |
| 生成条件 | — | 只对 **≤64MB 非固实图片**，每帧 ≤4 张 |
| 折射层 | 会进 | **永不进** |

### 17.5 状态栏"会说话"

hover/选中时**改变左区文字**（40ms 节流、不触发引擎 I/O、**文字变但位置不跳**）。
对比度 4.59:1 → **≥7:1**（`#A6A6AA` 实测 7.70:1）。

### 17.6 动效规格

**160ms `cubic-bezier(.2, 0, 0, 1)`**；同轴滑动 ≤320px，>320px 直接切断；
移动时 24px 尾迹，静止无尾迹。

### 17.7 光晕断言的正确取样

取**相邻 tile 之间的间隙**，不是 tile 外侧环带：

| 取样 | 色度 |
|---|---|
